# Hosted dashboard connector validation

The static frontend at `https://ca.eduardoaugusto.work` is hosted in the separate `codex-accounts-proxy` repository. The main backend accepts authenticated requests from that exact origin and retains capability-path, CSRF, loopback binding, and shared-session idle checks. The private IPC and direct local dashboard remain available. CLI and automatic panel opening pass the local endpoint in a fragment, not a query parameter.

Validation completed with `TMPDIR=/var/tmp bun run test:all`: all 11 stages passed in 88.2 seconds, including 31 unit tests. The integration scenarios verify hosted-origin HTML reads, OPTIONS/private-network preflight, rejection of untrusted origins, capability-free requests, and invalid CSRF tokens. Existing authentication, switching, automatic continuation, terminal restoration, and quota-reset scenarios passed. Marketplace bundles were regenerated by the suite. The seven-page MDX build and the hosted frontend's browser-JavaScript build also passed.

Browser visual testing and the browser's local-network permission flow were not exercised: the available browser host was unavailable. Browsers can block loopback requests based on their permission settings. The frontend provides a direct-local-panel fallback and explains reconnecting after backend restart. Live-account validation was not performed; all backend scenarios used fake identities and local services.

The hosted repository has no server runtime, telemetry, or credential relay. It is a trusted frontend capable of operating the local panel after pairing, so repository publishing access remains security-sensitive. Pairing is tab-scoped; a fresh tab or a restarted backend can require a new `codex-accounts panel` invocation.
